# FocusFlow

FocusFlow — русскоязычное адаптивное приложение с самостоятельно создаваемыми списками и задачами, Pomodoro-таймером и учётными записями с облачной синхронизацией.

## Требования

- Node.js 20.19+ или 22.12+
- npm

## Установка и запуск

```bash
npm install
npm run dev
```

Откройте адрес, напечатанный Vite в терминале (обычно `http://localhost:5173`).

## Проверка и production-сборка

```bash
npm run build
npm run preview
```

## Возможности

- Создание, изменение, удаление и завершение задач с приоритетами.
- Создание, переименование и удаление пользовательских списков.
- Фильтры, сохранение демонстрационных планов в `localStorage`.
- Аккаунты, сброс пароля и безопасная синхронизация планов через Supabase.
- Pomodoro-таймер с запуском, паузой и сбросом.
- Прогресс списка и демонстрационная недельная диаграмма.
- Пользовательское соглашение, информация о конфиденциальности и канал поддержки.

Демо-режим не требует учётной записи и сохраняет планы только в браузере. Для регистрации и синхронизации настройте Supabase:

1. Создайте проект в [Supabase](https://supabase.com/), затем откройте **SQL Editor** и выполните `supabase/schema.sql`.
2. В Supabase **Authentication → URL Configuration** добавьте адрес сайта в **Redirect URLs**: `https://pingpingov91-wq.github.io/focusflow-app/`. Настройте подтверждение электронной почты и SMTP в настройках авторизации.
3. В GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` из настроек проекта Supabase. Это только публичный URL и ключ `anon`/`publishable`; **никогда не публикуйте `service_role`**. Таблицы и политики RLS в SQL ограничивают доступ к данным аккаунтом пользователя.
4. Добавьте GitHub Actions variable `VITE_SUPPORT_EMAIL` с настоящим адресом поддержки **до включения регистрации**. Аккаунты появятся только после настройки всех трёх переменных. До этого посетительские обращения направляются в публичные GitHub Issues; не указывайте там персональные данные. Для приватных запросов об аккаунте настройте почту поддержки.
5. В Supabase добавьте тот же опубликованный адрес в **Authentication → URL Configuration → Redirect URLs**.
6. Повторно отправьте изменения в `main`: GitHub Actions пересоберёт и опубликует сайт с настройками аккаунтов.

## Публикация на GitHub Pages

При отправке изменений в ветку `main` GitHub Actions автоматически соберёт и опубликует приложение. В настройках репозитория **Settings → Pages → Build and deployment → Source** должна быть выбрана опция **GitHub Actions**. Сайт: `https://pingpingov91-wq.github.io/focusflow-app/`.

Для проверки сборки с адресами GitHub Pages локально выполните:

```bash
npm run build -- --mode github-pages
```

### Локальная настройка аккаунтов

Для локальной регистрации скопируйте `.env.example` в `.env.local`, укажите URL проекта, публичный ключ Supabase и настоящий `VITE_SUPPORT_EMAIL`, а затем перезапустите `npm run dev`. Без всех трёх настроек регистрация выключена, деморежим и пользовательские списки в текущем браузере работают. Включить SMTP и подтверждение почты необходимо в Supabase Auth. Добавлять `service_role`-ключ в `VITE_*`, браузер или GitHub Pages нельзя.

Текст пользовательского соглашения и политики конфиденциальности отображается в приложении. Перед коммерческим запуском владелец должен заполнить сведения о себе, проверить регион обработки данных и получить юридическую проверку документов.
